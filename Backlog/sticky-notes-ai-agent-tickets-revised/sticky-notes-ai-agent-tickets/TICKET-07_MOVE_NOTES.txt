TICKET ID: SN-07
TITLE: Implement note movement from the draggable header background
PRIORITY: BLOCKING / CORE INTERACTION 1
DEPENDS ON: SN-03, SN-05, SN-06
PRIMARY FILES:
- src/features/board/useBoardGestures.ts
- src/features/board/Board.tsx
- src/features/board/NoteCard.tsx
- src/features/board/Board.css

GOAL
Allow a note to be moved by dragging only its header's draggable background while keeping the note clamped inside the board.

START RULES
Movement starts only when:
- Pointer start passes the global primary-left-button gate.
- The pointerdown originates from the designated draggable header background.
- No other gesture is active.

The following must NOT initiate movement:
- Textarea.
- Resize handle.
- Buttons or controls inside the header.
- General note body.

START SEQUENCE
On valid header pointerdown:
1. Stop propagation only as needed to prevent empty-board selection/creation behavior.
2. Select the note and request bring-to-front through stable Board callbacks.
3. Measure boardSurface bounds.
4. Measure trash zone bounds in board coordinates, because the moving Gesture snapshots trashRect.
5. Convert the start client point to BoardPoint.
6. Snapshot the note's committed rect as initialRect.
7. Store a moving Gesture with pointerId, noteId, pointerOrigin, latestPointer, initialRect, boardBounds, and trashRect.
8. Capture the pointer on the header start element.
9. Mark gesture-active UI state.

MOVEMENT PREVIEW
For each scheduled animation frame while moving:
- Compute rect with moveRect(initialRect, pointerOrigin, latestPointer, boardSize).
- Store preview as { noteId, rect }.
- Do not mutate committed reducer state during pointermove.
- Keep the full note clamped inside the board.
- Update trash-active state using the exact isPointerOverTrash helper and the latest pointer, not note overlap.

COMMIT
On matching pointerup:
- Recompute the final pointer from the release event.
- Recompute the final moved rectangle with moveRect.
- If release pointer is not over trash, commit noteRectCommitted.
- Trash deletion is completed in SN-10, but the move commit design must make that branch possible.
- Clear all gesture/preview state through the shared commit path.

INTERACTION DETAILS
- The note should visually follow the pointer through previewRect.
- Use grab cursor when idle over the draggable header.
- Use grabbing cursor while moving.
- boardSurface[data-gesture-active="true"] must disable user-select.
- Textarea selection must remain enabled outside active board gestures.
- Pointer leaving the note or board visual area must not terminate the captured sequence prematurely.

Z-ORDER
- A moved note must become selected and frontmost at interaction start.
- Bring-to-front must not create duplicate notes.
- If already frontmost, reducer identity no-op must be preserved.

OUT OF SCOPE
- Resize.
- Create.
- Final trash deletion branch.
- Keyboard movement.
- Physics/inertia/animations.

ACCEPTANCE CRITERIA
- Dragging the header background moves the note.
- Dragging the textarea or resize handle does not move the note.
- The note never commits outside board bounds.
- Committed position is based on pointerup coordinates.
- Movement remains active after the pointer leaves the header because capture is held.
- Raw pointermove does not dispatch reducer actions.
- Selected/frontmost behavior occurs at start.
- Escape/pointercancel/lost capture restores the committed rectangle without committing the preview.

MANUAL VERIFICATION
- Move a note toward all four board edges.
- Move quickly and release before the next animation frame; committed geometry must match release position.
- Start movement, leave the note, and release elsewhere.
- Start movement and press Escape; note returns to committed position.
- Confirm textarea text selection does not accidentally move the note.

DONE WHEN
Movement is reliable enough to satisfy the core checkpoint independently of create, resize, and delete.
