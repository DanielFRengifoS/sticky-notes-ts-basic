TICKET ID: SN-04
TITLE: Implement the focused reducer for committed note state
PRIORITY: BLOCKING
DEPENDS ON: SN-02
PRIMARY FILES:
- src/domain/notesReducer.ts
- src/domain/notesReducer.test.ts (tests may be finalized in SN-15)

GOAL
Implement a small pure reducer that owns only committed document changes and preserves object/state identity wherever no actual change occurs.

ACTION UNION
Define and export:

type NotesAction =
  | { type: "notesHydrated"; notes: Note[] }
  | { type: "noteAdded"; note: Note }
  | { type: "noteRectCommitted"; noteId: NoteId; rect: NoteRect }
  | { type: "noteTextChanged"; noteId: NoteId; text: string }
  | { type: "noteBroughtToFront"; noteId: NoteId }
  | { type: "noteRemoved"; noteId: NoteId };

INITIAL STATE
Export a simple initial state:
{ notes: [] }

REDUCER BEHAVIOR

1. notesHydrated
- Replace the current notes array with the supplied validated and normalized notes.
- This action is intended to run once before Board phase becomes "ready".
- Do not select or focus any restored note in the reducer.

2. noteAdded
- Append the note.
- Appending makes it frontmost.
- Do not independently reorder existing notes.

3. noteRectCommitted
- Find the target by ID.
- If missing, return the exact existing state object.
- Replace only the targeted Note object.
- Preserve all unaffected Note object references.
- If the supplied rect is reference-equal or value-equal to the current rect, returning the current state is preferred.

4. noteTextChanged
- Find the target by ID.
- If missing, return the exact existing state object.
- If text is unchanged, return the exact existing state object.
- Replace only the targeted Note object.
- Do not perform storage writes here.
- Text-length enforcement should occur consistently at the event boundary and/or reducer; never allow committed text to exceed MAX_NOTE_TEXT_LENGTH.

5. noteBroughtToFront
- Find the target by ID.
- If missing, return the exact existing state object.
- If already the final array item, return the exact existing state object.
- Otherwise return a new array with the target moved to the final position.
- Preserve every Note object reference, including the moved note.

6. noteRemoved
- Find the target by ID.
- If missing, return the exact existing state object.
- Return a new state containing all other note objects with their references preserved.

STRICT OWNERSHIP RULES
The reducer MUST NOT:
- Measure the DOM.
- Read or write storage.
- Track active pointer gestures.
- Manage focus.
- Schedule animation frames.
- Generate IDs.
- Normalize rectangles against current DOM bounds.
- Own selectedId, pendingFocusId, board tool, or board phase.

PERFORMANCE/REFERENCE CONTRACT
- Array order is z-order.
- Only a real document change creates a new state.
- Unaffected notes retain identity so React.memo can prevent unnecessary NoteCard renders.
- Missing-ID actions are no-ops by identity.
- Frontmost bring-to-front is a no-op by identity.

ACCEPTANCE CRITERIA
- Reducer is pure and deterministic.
- Every action above is implemented.
- No-op identity behavior is covered by tests.
- Unaffected note references are preserved.
- No UI or infrastructure concern leaks into this file.
- Strict TypeScript passes without any.

DONE WHEN
Committed note changes have one predictable state transition layer that supports memoized rendering and easy unit testing.
