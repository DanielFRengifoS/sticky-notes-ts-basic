TICKET ID: SN-16
TITLE: Run complete interaction verification and fix only must-ship defects
PRIORITY: BLOCKING BEFORE SUBMISSION
DEPENDS ON: SN-01 through SN-15
PRIMARY OUTPUT:
- A stable application; code changes may touch any existing implementation file
- A short internal verification record for use in README

GOAL
Verify the complete application as a cohesive system, prioritize defects in the four core interactions, and avoid adding optional scope.

CORE CHECKPOINT
Before any additional polish, manually verify all four:
- Create.
- Move.
- Resize.
- Delete through trash.

If any fail, stop and fix them before editing, persistence, styling, or optional work.

REQUIRED MANUAL VERIFICATION MATRIX

1. CREATE
- Arm create mode.
- Drag in multiple directions.
- Release below threshold: no note; tool remains armed.
- Valid release: one note; selected; focused; tool returns select.
- Create near every board edge.
- Fast release before scheduled animation-frame callback.
- Escape during creation.

2. EDIT
- Type text immediately after creation.
- Use caret, selection, copy/paste, and multiline input.
- Confirm 5000-character cap.
- Confirm editing does not move/resize note.

3. MOVE
- Drag from header background.
- Try pointerdown on textarea/header control/resize handle; no move.
- Leave note while moving; capture continues.
- Clamp against all board edges.
- Fast release before preview frame.
- Escape, pointercancel scenario if reproducible, and capture-loss behavior.

4. RESIZE
- Resize larger and smaller.
- Enforce minimum.
- Clamp to board right/bottom.
- Fast release.
- Escape.

5. STACKING/SELECTION
- Overlap at least two notes.
- Interact with rear note via header and textarea.
- Confirm it becomes frontmost.
- Click empty select-mode board and confirm selection clears.
- Delete selected note and confirm selection clears.

6. TRASH
- Active styling follows pointer.
- Pointer exactly on edge is inactive.
- Note overlap without pointer inside does not delete.
- Pointer inside deletes even if note is elsewhere.
- Escape while active does not delete.
- Trash does not block pointer events.

7. PERSISTENCE
- Create/edit/move/resize and wait for debounce.
- Reload and confirm text, geometry, and stacking order.
- Confirm restored notes do not autofocus.
- Confirm no write before hydration.
- Invalid JSON opens usable empty board.
- Storage failure leaves app usable.

8. LAYOUT
- Test exactly 1024 x 768.
- No horizontal scroll.
- Toolbar and board both usable.
- Minimum-size note editor usable.
- Trash instructions visible.

9. BROWSERS
Where available, test current:
- Chrome.
- Firefox.
- Edge.
Record only the browsers/OS actually tested. Do not fabricate results.

10. BUILD/QUALITY
Run:
npm run check

The command must catch:
- Type errors.
- Lint failures.
- Unit-test failures.
- Production bundling failures.

DEFECT PRIORITY
Fix in this order:
P0:
- Data loss.
- Pre-hydration overwrite.
- Gesture commits on cancellation.
- Wrong note deleted.
- Pointerup final geometry incorrect.
P1:
- Core interaction unreliable.
- Event boundary causes accidental move/create.
- Board clamping broken.
- Focus/editing unusable.
P2:
- Styling or guidance issue.
- Minor layout defect.
Do not implement optional features while any P0/P1 issue exists.

CODE CLEANUP
- Remove temporary static notes.
- Remove unused abstractions.
- Remove speculative comments.
- Ensure comments are English and explain only non-obvious behavior.
- Ensure no console noise/errors in normal use.
- Ensure architecture still matches frozen file ownership.

ACCEPTANCE CRITERIA
- Every manual scenario above has been run or explicitly marked unavailable.
- All discovered P0 and P1 defects are fixed.
- npm run check passes.
- Production app works after npm run build.
- The implementation remains inside frozen scope.
- Verified browser/OS facts are recorded for README.

DONE WHEN
The implementation is stable enough that remaining work is documentation and submission packaging, not feature engineering.
