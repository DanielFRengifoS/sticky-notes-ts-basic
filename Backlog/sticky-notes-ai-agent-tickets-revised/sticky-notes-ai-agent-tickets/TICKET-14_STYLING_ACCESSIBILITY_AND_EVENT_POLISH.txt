TICKET ID: SN-14
TITLE: Complete interaction styling, accessibility state, and desktop usability polish
PRIORITY: MUST SHIP
DEPENDS ON: SN-07, SN-08, SN-09, SN-10, SN-11, SN-13
PRIMARY FILES:
- src/features/board/Board.css
- src/features/board/Board.tsx
- src/features/board/NoteCard.tsx
- src/App.tsx

GOAL
Make the finished interaction model understandable and usable without adding decorative scope or compromising pointer/text behavior.

REQUIRED POINTER-EVENT CSS
Set:
.creationPreview,
.emptyState,
.trashZone {
  pointer-events: none;
}

Set:
.noteEditor {
  resize: none;
}

Set:
.noteHeader,
.resizeHandle {
  touch-action: none;
}

Set behavior equivalent to:
.boardSurface[data-gesture-active="true"] {
  user-select: none;
}

Do not globally disable user selection. Textarea selection must remain enabled whenever a board gesture is not active.

CURSORS
- Draggable header: grab.
- Active move: grabbing.
- Resize handle: nwse-resize.
- boardSurface in create mode: crosshair.
- Default surface/select mode: ordinary cursor.

VISUAL FEEDBACK
- Clear selected-note styling.
- Creation preview visibly differs from a committed note.
- Trash inactive/active states are obvious.
- Trash activation is not communicated through color alone.
- Show text equivalent to "Release while the cursor is over the trash."
- Empty-state guidance explains how to create a note.
- Armed create button label explains the next action.
- No decorative transitions during create/move/resize.
- Small non-gesture hover/focus transitions are acceptable only if they do not obscure behavior.

ACCESSIBILITY
- Create button has aria-pressed reflecting tool === "create".
- Buttons use native button elements.
- Textarea has an accessible label, visible or aria-label.
- Resize handle must be identifiable to assistive technology if rendered as a control; if it is a non-keyboard pointer target, give a meaningful aria-label/role only when semantically accurate.
- Preserve visible focus indicators.
- Do not claim full keyboard operability for drag/resize if not implemented.
- Trash instructions must not rely only on an icon.

LAYOUT
- Minimum target resolution: 1024 x 768.
- Toolbar must leave adequate room for board.
- Page must not create horizontal scrolling at target resolution.
- Board remains large enough to create and manipulate notes.
- Notes and trash remain inside boardSurface.
- boardFrame decoration must not affect coordinate calculations.
- A note editor should remain usable at minimum note size 160 x 120.

Z-INDEX
- Notes follow reducer array order.
- Trash renders visually above notes.
- Creation preview renders above or clearly visible relative to notes without intercepting input.
- Avoid arbitrary unbounded z-index values; Board can derive z-index from array index.

EVENT POLISH
- Buttons/textarea do not initiate movement.
- Resize handle does not initiate movement.
- Note interaction does not bubble into empty-board create/clear behavior.
- Empty-state and trash overlays do not block board pointerdown.
- No native textarea resize affordance conflicts with custom resizing.
- No text gets selected while actively dragging a note.

BROWSER-SAFE CSS
Use broadly supported current-browser CSS for Chrome, Firefox, and Edge. Avoid experimental features that are unnecessary for the assessment.

OUT OF SCOPE
- Different note colors.
- Themes.
- Animations.
- Touch-first/mobile layout.
- Delete key.
- Undo/redo.
- WCAG certification claims.

ACCEPTANCE CRITERIA
- Every required cursor and interaction state is visible.
- Create button state is exposed through aria-pressed and label change.
- Trash activation has a non-color-only cue.
- Text editing and selection remain usable.
- Overlay elements do not capture pointers.
- Layout passes at exactly 1024 x 768 without horizontal scrolling.
- Styling does not introduce a second coordinate offset into boardSurface.
- No decorative motion causes lag or geometry mismatch.

DONE WHEN
A reviewer can understand how to create, move, resize, edit, front, and delete notes without reading the code, and event boundaries remain correct.
