TICKET ID: SN-05
TITLE: Render committed notes through a memoized NoteCard with stable Board handlers
PRIORITY: BLOCKING
DEPENDS ON: SN-01, SN-02, SN-04
PRIMARY FILES:
- src/features/board/Board.tsx
- src/features/board/NoteCard.tsx
- src/features/board/Board.css

GOAL
Establish the React component contract for notes before implementing pointer gestures. Render notes according to reducer order and ensure unchanged notes can avoid rerendering.

BOARD RESPONSIBILITIES IN THIS TICKET
- Initialize useReducer with notesReducer.
- Render notes in array order; the final note must visually be frontmost.
- Maintain provisional selectedId and pendingFocusId state if needed, but full behavior is completed in SN-11.
- Define stable callbacks with useCallback.
- Avoid creating per-note closures in the render loop.

REQUIRED NOTE CARD CONTRACT
Use a prop contract functionally equivalent to:

<NoteCard
  key={note.id}
  note={note}
  previewRect={
    preview?.noteId === note.id ? preview.rect : undefined
  }
  selected={selectedId === note.id}
  pendingFocus={pendingFocusId === note.id}
  onTextChange={handleTextChange}
  onHeaderPointerDown={handleHeaderPointerDown}
  onResizePointerDown={handleResizePointerDown}
  onFocusRequestConsumed={handleFocusRequestConsumed}
/>

Exact prop names may differ slightly, but the behavior and stability contract must not.

NOTE CARD REQUIREMENTS
- Export with React.memo:
  export const NoteCard = memo(NoteCardComponent);
- Do not add a custom comparison function unless a measured issue proves it necessary.
- Use previewRect when supplied; otherwise use note.rect.
- Position via absolute CSS inside boardSurface.
- Pass note.id into stable Board callbacks from inside NoteCard.
- Render:
  - A note container.
  - A header with a draggable background region.
  - Any header control region separated from the draggable region.
  - A controlled textarea editor.
  - A bottom-right resize handle.
- Do not make the entire note draggable.
- Buttons or controls inside the header must not start movement.
- The textarea must not start movement.
- The resize handle alone starts resize.

STABLE-PROP REQUIREMENTS
- Board callbacks remain stable across ordinary renders.
- The notes render loop does not create new callback closures for each note.
- Only the active note receives changing preview geometry.
- Unaffected note objects retain identity through reducer behavior.
- Unaffected NoteCard props remain stable.

BASIC TEXT EDITING BOUNDARY
- Textarea value comes from note.text.
- onChange reports note ID and text to Board.
- Do not write storage from NoteCard.
- Enforce MAX_NOTE_TEXT_LENGTH at the event/reducer boundary.
- Set resize: none in CSS.
- Text selection must remain enabled.

BASIC CSS/EVENT BOUNDARIES
- noteHeader and resizeHandle: touch-action: none.
- resizeHandle: generous hit area and nwse-resize cursor.
- Header: grab cursor; active movement will later use grabbing.
- Selected styling can be provisional but must be visible by SN-14.
- Avoid decorative transitions that would interfere with gesture preview.

TEMPORARY DEVELOPMENT DATA
It is acceptable to render one or two temporary static notes while building this ticket, but remove all hard-coded notes once reducer/hydration integration is complete.

OUT OF SCOPE
- Full movement/resize logic.
- Creation.
- Trash deletion.
- Persistence.
- Focus-after-creation behavior.
- Final accessibility/state polish.

ACCEPTANCE CRITERIA
- Notes render in array order.
- NoteCard is memoized.
- A preview rectangle can override only the active note's committed rectangle.
- Textarea is controlled.
- Header, textarea, header controls, and resize handle have separate event boundaries.
- No per-note callback closure is created in Board's map loop.
- Strict TypeScript and lint pass.

DONE WHEN
The board has a performant, stable component boundary ready for gesture handlers without mixing temporary pointer state into committed note data.
