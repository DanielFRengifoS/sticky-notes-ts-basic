TICKET ID: SN-10
TITLE: Implement pointer-targeted trash activation and delete-on-release
PRIORITY: BLOCKING / CORE INTERACTION 4
DEPENDS ON: SN-03, SN-07
PRIMARY FILES:
- src/features/board/useBoardGestures.ts
- src/features/board/Board.tsx
- src/features/board/Board.css

GOAL
Delete a moving note only when the release pointer is strictly inside the predefined trash rectangle, while using the identical hit-test for preview activation and final commit.

TRASH ZONE RENDERING
- Render the trash zone inside boardSurface.
- It must appear visually above notes.
- Set pointer-events: none so it never captures pointer input.
- Include explicit guidance equivalent to: "Release while the cursor is over the trash."
- Provide inactive and active visual states.
- Active state must change icon, text, shape, or another non-color-only signal.
- Do not rely on color alone.

TRASH GEOMETRY
At movement start:
- Measure the trash zone client rect.
- Convert it into board coordinates relative to boardSurface.
- Store this NoteRect as trashRect in the moving Gesture.
- Do not use visual note overlap to detect deletion.

PREVIEW ACTIVATION
During movement frame calculation:
- Compute latest pointer in board coordinates.
- Set trash active using only:
  isPointerOverTrash(latestPointer, gesture.trashRect)
- Do not reproduce the inequality inline.
- A pointer exactly on the trash edge is inactive.
- The moving note itself remains clamped inside the board; it does not need to overlap the trash zone.

BOARD REMOVAL HELPER - OWNED BY SN-10
Define one stable Board helper and make it the only Board-level removal entry point:

const removeNote = useCallback((noteId: NoteId) => {
  dispatch({ type: "noteRemoved", noteId });
  setSelectedId(current => (current === noteId ? null : current));
  setPendingFocusId(current => (current === noteId ? null : current));
}, []);

Ownership rules:
- SN-10 owns this helper and the removal invariants it encodes.
- The gesture hook should receive or invoke this stable callback at the delete commit boundary according to the existing hook API.
- Do not dispatch noteRemoved directly from the trash path in addition to calling removeNote.
- Future removal surfaces, if any are deliberately added, must reuse removeNote rather than duplicate selection/focus cleanup.
- Reducer remains unaware of selection and focus.

COMMIT BRANCH
On movement pointerup:
1. Recompute final release BoardPoint from the event.
2. Evaluate isPointerOverTrash(finalPointer, copiedGesture.trashRect).
3. If true:
   - Call removeNote with the moving note ID.
   - Do not also dispatch noteRectCommitted.
4. If false:
   - Commit the final move rectangle normally.
5. Clear gesture, preview, active trash state, and capture through the shared commit path.

SELECTION STATE
- removeNote clears selectedId only when it references the removed note.
- removeNote clears pendingFocusId only when it references the removed note.
- Removing another note does not clear the current selection or unrelated pending focus.

CANCELLATION
- Escape, pointercancel, capture loss, and unmount never delete.
- Trash active styling must clear on every cancellation path.

EMPTY/CREATE INTERACTION
- Creation must not start when the initial pointer is over the trash zone.
- The trash itself remains pointer-events none, so Board must explicitly check the pointer position against trash bounds before starting creation.

OUT OF SCOPE
- Delete key support.
- Clicking the trash.
- Dragging the note rectangle into trash based on overlap.
- Undo.
- Animating deletion.

ACCEPTANCE CRITERIA
- The same isPointerOverTrash function drives active styling and deletion.
- Deletion is based on the release pointer, not note overlap.
- Strict edge behavior is correct.
- Trash deletion goes through the stable Board removeNote helper.
- A deleted selected note clears selection and a matching pending focus request.
- Releasing outside trash commits movement, not deletion.
- Cancellation never deletes.
- Trash guidance is visible and non-color-only.
- Trash zone does not intercept pointer events.

MANUAL VERIFICATION
- Hover release pointer inside, outside, and exactly on each trash edge.
- Move a note whose rectangle overlaps trash while the pointer is outside; it must not delete.
- Put the pointer over trash while the note is elsewhere; it must delete.
- Activate trash then press Escape; note remains.
- Verify creation cannot start over trash.

DONE WHEN
All four required core interactions - create, move, resize, delete - work reliably and the 2:30 core checkpoint can be passed.
