TICKET ID: SN-11
TITLE: Complete selection, bring-to-front, text editing, focus coordination, empty-board behavior, and Escape handling
PRIORITY: MUST SHIP
DEPENDS ON: SN-04, SN-05, SN-07, SN-08, SN-09, SN-10
PRIMARY FILES:
- src/features/board/Board.tsx
- src/features/board/NoteCard.tsx
- src/features/board/Board.css

GOAL
Finish non-persistence UI state and editing behavior without moving focus or transient pointer state into the notes reducer.

BOARD STATE
Board owns:
- selectedId: NoteId | null
- pendingFocusId: NoteId | null
- tool: BoardTool
- phase is added/integrated in persistence tickets
- Active gesture preview comes from useBoardGestures, not reducer

SELECTION RULES
1. Creating a note - established by SN-09 and verified here:
   - Adds it.
   - Selects it.
   - It is frontmost because noteAdded appends it.
   - Sets pendingFocusId.
   - Returns tool to "select".
   - Do not move these creation side effects into a second competing path; SN-11 completes focus consumption and verifies the SN-09 behavior.

2. Interacting with an existing note:
   - Select it.
   - Dispatch noteBroughtToFront.
   - This includes interaction with the header, resize handle, textarea, and note controls.
   - Textarea/control interactions must not initiate movement.

3. Empty board in select mode:
   - A primary left click on empty boardSurface clears selectedId.
   - It must not clear selection when the event originated from a note.
   - It must not start creation unless tool is "create".

4. Removal - reuse SN-10 ownership:
   - Verify and reuse the stable removeNote helper introduced in SN-10.
   - Do not reimplement noteRemoved dispatch plus selectedId/pendingFocusId cleanup in SN-11.
   - Removing the selected note clears selectedId through that helper.
   - A matching pendingFocusId is cleared through that helper.

5. Hydration:
   - Restored notes begin with no selection.
   - Restored notes never autofocus.

TEXT EDITING
- Textarea remains fully controlled.
- Dispatch noteTextChanged immediately on each input.
- Limit committed text to MAX_NOTE_TEXT_LENGTH.
- Do not debounce React text state.
- Storage writes are debounced later, not typing.
- Preserve text selection and native editing behavior.
- Clicking/focusing textarea selects and brings note front without starting movement.
- Prevent pointerdown propagation only as necessary; do not break caret placement or text selection.

FOCUS AFTER CREATION
Implement one explicit focus request:
- NoteCard receives whether pendingFocusId matches its note.
- A textarea callback ref or useLayoutEffect focuses the textarea when pendingFocus is true.
- After focusing, NoteCard calls stable onFocusRequestConsumed(noteId).
- Board clears pendingFocusId only if it still matches that ID.
- Avoid repeat focus on future renders.
- Do not autofocus hydrated notes.

ESCAPE BEHAVIOR
At Board/window event boundary:
- If an active gesture exists, call cancelActiveGesture("escape").
- If tool === "create", set tool to "select".
- One Escape press during active create should both cancel and disarm.
- Escape must never commit preview geometry.
- Do not add Delete-key support.

HEADER CONTROL BOUNDARY
If a header includes any button/control:
- It selects and brings front as appropriate.
- It does not initiate movement.
- Stop propagation only to maintain the intended boundary.
No delete button is required.

SELECTED STYLING
- Make selected note clearly identifiable.
- Do not use selection styling as the only accessible interaction feedback.
- Ensure frontmost order visually matches reducer array order.

HANDLER STABILITY
Use stable useCallback handlers:
- handleTextChange(noteId, text)
- handleHeaderPointerDown(noteId, rect, event)
- handleResizePointerDown(noteId, rect, event)
- handleNoteInteraction(noteId)
- handleFocusRequestConsumed(noteId)
No per-note closures in Board's map loop.

ACCEPTANCE CRITERIA
- Text editing is immediate and controlled.
- Text is capped at 5000 characters.
- Any note interaction selects and brings it front.
- Already-frontmost interaction preserves reducer state identity.
- Empty select-mode board click clears selection.
- Created note focuses exactly once.
- Hydrated notes do not autofocus.
- Escape cancels active gestures and disarms create mode without committing.
- Textarea caret/selection behavior remains native.
- No selection/focus state exists in notesReducer.
- Removal invariants have one implementation: the SN-10 removeNote helper.
